How it works

1Where the end effector is

p(q) = ( L₁ cos q₁ + L₂ cos(q₁+q₂) , L₁ sin q₁ + L₂ sin(q₁+q₂) )

Two angles decide where the end effector is, and everything below is a rule about that one point.

ṗ = J(q) q̇ , J(q) = [ −L₁s₁ − L₂s₁₂ , −L₂s₁₂ ; L₁c₁ + L₂c₁₂ , L₂c₁₂ ] det J = L₁L₂ sin q₂

The Jacobian turns joint speeds into end-effector speed. Its first column is ẑ × (end effector − base) and its second is ẑ × (end effector − elbow): each column is the velocity you get by spinning the segment it belongs to. det J vanishes at q₂ = 0 or ±π — arm fully stretched or fully folded — and there the radial direction is unreachable at any joint speed. The command is the joint velocity itself, q̇ = u, which is what makes everything below linear in u.

2Where you want to go

v = (p* − p) · min( kp , vmax / ‖p* − p‖ ) then (JTJ + λ²I) unom = JTv

Head straight at the target, never faster than the speed cap. This controller has never heard of the obstacle and it is never replanned — every curve you are about to see is the filter’s doing, not a smarter plan.

The cap is applied to the Cartesian velocity before the inverse, so the unfiltered motion is a genuine constant-speed straight line — the reference the detour is read against. The inverse is damped least squares rather than J⁻¹, and det(JᵀJ + λ²I) ≥ λ⁴ > 0 for every pose, so there is no singular case to special-case; writing if (|det J| < ε) would put back exactly the discontinuity that damping exists to remove. λ is a length and scales with the arm (0.10 m here), which caps the joint-speed gain, so near full stretch the arm refuses the radial command and sweeps sideways instead of exploding. Anything genuinely time-optimal would need a double-integrator model and a higher-order CBF — a different lesson.

3What is forbidden

h(p) = √(ab) · [ ( (|x′|/a)2/ε + (|y′|/b)2/ε )ε/2 − 1 ]
h > 0outside — safe
h = 0exactly on the boundary
h < 0inside — the rule is violated

One formula draws every forbidden region: ε = 1 is the ellipse you drag out yourself, and a small ε squares off the corners so the region hugs the rectangular obstacle. The obstacle and a region you drew are the same rule, one more h. The √(ab) in front turns the shape value into metres of clearance, so h is very nearly the gap you can see on screen.

∂h/∂x = √(ab) · ( (|x′|/a) / F )2/ε − 1 · sgn(x′) / a F is the bracket above

Taking the ε/2-th root of the superquadric sum is a monotone rescale that fixes zero, so the zero level set, the safe set and the CBF property are all untouched — but the raw sum grows like distance2/ε, which at ε = 0.25 overflows outright far from the shape and would throttle the arm to a fraction of a sensible approach speed while it is still half a metre away. With the root, ‖∇h‖ stays between √(b/a) and √(a/b), so h is the signed distance to within that factor and is exact for a circle — which is what lets one α mean the same thing for both shapes. The absolute values cause no kink for ε < 2, and ∇h vanishes at exactly one point, the centre, which the code guards. There is no separate clearance term: the outline you see is the h = 0 curve, and the region is the whole statement of what is forbidden.

The obstacle is a rectangle and stays one; ε shapes the region around it, which is always the superellipse that just contains the rectangle — at the corner (a, b) we need (a/A)2/ε + (b/B)2/ε = 1, so A = 2ε/2·a. At ε → 0 the region is the rectangle itself; at ε = 1 it is the ellipse circumscribing it. Slide ε and watch the same object acquire a tighter or a more generous rule.

On vocabulary: the set where h ≥ 0 is the safe set, and that name is standard. Its complement has no single canonical name — papers say unsafe set or avoid set, applications say obstacle, and aerospace work says keep-out zone. “Forbidden region” is the phrasing used here, and it is also the established term in the virtual-fixtures literature, where a forbidden-region virtual fixture is exactly this: a software constraint that keeps a tool out of a volume.

4How h is allowed to change

ḣ = ∂h/∂p · ∂p/∂q · q̇ = ∇h(p)T J(q) u ≥ −α h

The rule is not “never get closer than a metre”. It is: the closer you are, the slower you may approach. −αh is an approach budget that uses itself up — on the boundary h = 0, so the budget is zero, so ḣ ≥ 0, and you are guided along the boundary instead of through it. Because h is in metres, α reads off directly: at α = 2 you may close at 2 m/s for every metre of clearance, so at 10 cm you may close at 20 cm/s. In Expert mode that number is the ruler drawn on the end effector; watch it shrink to nothing as the arm arrives.

h(t) ≥ h(0) e−αt

α·h is the simplest extended class-K function; any strictly increasing α(·) with α(0) = 0 works, and it must be defined for h < 0 too, which is what makes the line above legal there. Enforcing the inequality for all time gives that bound by the comparison lemma: forward invariance if you start safe, and exponential recovery if you start inside a region. Because the robot is velocity-commanded, u already appears in the first derivative of h (relative degree 1), which is why a single inequality that is linear in u suffices — command torque instead and u drops out of ḣ, and you need a higher-order CBF. The guarantee is continuous-time; we integrate with explicit Euler at Δt = 1/240 s, and αΔt ≤ 1 is what carries the argument across the discretisation (at the maximum α on the slider, αΔt ≈ 0.08).

5The filter

u = arg min ‖u − unom‖² subject to ∇hT J u ≥ −α h for every region

If the command is already safe, the filter hands it back untouched — that is what it means when the ghost arrow is nowhere to be seen, sitting exactly under the solid one. Otherwise it makes the smallest change that obeys every rule at once.

u lives in ℝ² and there are at most two rows, so the answer is one of four points: unom itself, its projection onto either row alone, or the intersection of both. Try all four and keep the feasible one of least cost — that is exact, because the objective is strictly convex, so the solution is the unique projection onto the feasible polygon, and no multiplier sign test is needed.

The filter can never fail while you are safe: if every h ≥ 0 then every right-hand side −αh ≤ 0, so u = 0 satisfies every row. Infeasibility requires some h to be negative already, and when it happens the enumeration certifies it for free — we stop the arm and say so rather than adding a slack variable and quietly trading away the guarantee.

Two honest caveats. “Minimal” is minimal in joint space; in task space the correction direction is JJᵀ∇h rather than ∇h, so the end effector also slows as it slides along a boundary, not only turns — that is correct, not a glitch. And safety is not liveness: the arm can legitimately stall with the target behind a region, and nothing in this maths promises otherwise. A filter keeps you safe; a planner makes you arrive.

WHAT is forbidden lives in h. HOW CAUTIOUSLY you approach lives in α. Draw a new shape and you have changed h. Move one slider and you have changed α. Nothing else in the controller needs to know.
